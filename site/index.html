Boots to the home screen · iOS 16.7.16 (20H392)

iOS 16 on the Xiaomi Mi 10T.

Apple's open-source XNU kernel, patched for the Snapdragon 865, boots the unmodified iOS system of the iPhone X on apollo: launchd, the daemons, SpringBoard and the stock apps. No emulator, and no Android underneath.

Close to a daily-usable phone
The UI, Wi-Fi, Bluetooth, sound, microphone and vibration work. Battery status, sleep, cameras and cellular are still to do.

How it boots

Every boot is temporary: nothing is flashed except the iOS root in userdata.

Xiaomi bootloader (unlocked)Stock, untouched. Rebooting without the next step starts Android's boot chain as usual.
fastboot boot shim-boot.imgA temporary boot image; nothing is written to the boot partition.
The shimLoads XNU, an Apple Device Tree built for the phone, and the boot options.
XNU kernel and driversUFS storage, display, touch, GPU, Wi-Fi, Bluetooth, audio, vibration, CPU clocks and temperature.
iOS root (HFS+) in userdataThe iPhone X's iOS 16.7.16 system, unmodified, plus small helper libraries.
launchd → daemons → backboardd + SpringBoard → appsCoreAnimation draws on the Adreno 650 through Mesa; the kernel page-flips the frames onto the panel.
No serial portThe kernel keeps a 4 MiB log at the end of userdata, read from recovery with tools/sweet-log-pull.sh.
First boot is slowA new root runs iOS's data migration once (an hour or more). Later boots take about a minute.
Built in the cloudThe kernel and the iOS programs build on GitHub Actions' macOS runners.

Getting started

What you need: a Mi 10T / 10T Pro with an unlocked bootloader; Linux with adb, fastboot, python3, aarch64-linux-gnu-gcc, mkbootimg and the GitHub CLI; a recovery with adb (OrangeFox) at recovery/recovery.img.

⚠️ This is an experiment. Most of Apple's security model is switched off, and installing the iOS root erases Android's userdata. Bootloaders, recovery, modem and persist are never touched.

Back up the phone

From the temporary recovery, pull at least persist, modemst1, modemst2, fsg, fsc, boot, dtbo and vbmeta, and keep them out of git. Then extract the stock device tree:

python3 tools/unpack_bootv2.py backup/boot.img dtb/boot_unpacked

Build the kernel and the iOS programs

Each workflow uploads an artifact; download them by run ID.

python3 tools/validate-repo.py      # checks the patch series in seconds
gh workflow run xnu.yml             # the kernel
gh workflow run userland.yml        # Mesa, the CoreAnimation bridge, libsweet-fix
gh workflow run audio.yml           # the audio plug-in
gh workflow run bt.yml              # the Bluetooth library
gh run watch RUN_ID --exit-status
gh run download RUN_ID -n xnu-kernel -D xnu/out
gh run download USERLAND_RUN_ID -n sweet-userland -D sweet-userland
gh run download BT_RUN_ID -n sweet-bt -D sweet-bt

Build and install the iOS root

tools/build-ios-root.sh downloads the iPhone X IPSW's disk images, builds the root, adds the programs and, after asking, writes it to userdata. Details: userland/README.md.

Get the firmware

Firmware comes from Xiaomi and Qualcomm and is never stored in git. See Firmware for each file and the tool that fetches it.

Build the boot image and boot

The full-featured setup: GPU-drawn UI at 60 Hz in full-panel mode, Wi-Fi, Bluetooth, sound, microphone, vibration and every iOS service.

python3 tools/mkadt.py shim/out/apollo.adt --highmem --display-height 2502 \
    --touch-fw research/apollo-fw/novatek_nt36675_j3s_fw01.bin \
    --gmu-fw research/apollo-gpu/a650_gmu.bin --sqe-fw research/apollo-gpu/a650_sqe.fw \
    --zap-mdt research/apollo-gpu/a650_zap.mdt --zap-seg research/apollo-gpu/a650_zap.b02 \
    --wifi-fw research/apollo-wifi --bt-fw research/apollo-bt \
    --file /usr/local/lib/libsweet-gl.dylib=sweet-userland/lib/libsweet-gl.dylib \
    --file /usr/local/lib/libsweet-fix.dylib=sweet-userland/lib/libsweet-fix.dylib \
    --file /usr/local/lib/libsweet-bt.dylib=sweet-bt/lib/libsweet-bt.dylib \
    --files-from tools/root-files/files.txt --files-from tools/root-files/bt-on.txt \
    --files-from tools/root-files/aegir-off.txt
python3 tools/mkpayload.py xnu/out/kernel.development.sweet shim/out/apollo.adt shim/out/payload.bin \
    --cmdline 'debug=0xc serial=3 cpumask=0xf1 keepsyms=1 -enable_kprintf_spam -noprogress rd=ufsroot0 unentitled_ios_sim_launch=1 ignition_level=1 wdt_test=no_user_checkin ufsrw=1 rootrw=1 launchd_unsecure_cache=1 wdt=-1 ufslogsecs=1 sweetfb_noconsole=1 sweetfb_height=2502 sweetfb_hz=60 sweetgpu=22 sweetgpukeep=1 sweetgpulevel=6 sweetwifi=12 apollo_audio=5 apollo_sound_gain=0 apollo_sound_below=80 apollo_mic=4 apollo_haptic=5 sweetbt=6 sweetinject=/usr/local/lib/libsweet-ca.dylib:backboardd;/usr/local/lib/libsweet-bt.dylib:bluetoothd,BlueTool sweetnull=backboardd,SpringBoard,bluetoothd,BlueTool,mediaserverd'
shim/build.sh ../shim/out/payload.bin   # → shim/out/shim-boot.img
fastboot boot shim/out/shim-boot.img

For a minimal first boot, drop everything after sweetfb_noconsole=1 and use cpus=1 instead of cpumask=0xf1. The boot line holds at most 607 characters.

Read the kernel log

Boot into recovery straight from the boot you want to look at; a new iOS boot overwrites the log.

fastboot boot recovery/recovery.img && adb wait-for-recovery
tools/sweet-log-pull.sh logs/boot.txt
adb reboot bootloader

tools/sweet-crash.py turns crash reports in the log into function names.

Repository layout

sweet / SWEET is the kernel's internal machine name; you'll see it in file, tool and option names.

xnu/patches/The kernel: patches 0001–0163 on Apple's xnu-8796, applied in order by CI.
shim/The boot shim, packed as an Android boot image.
wifi/The Linux compatibility layer the ath11k Wi-Fi driver is built on.
userland/Programs for the phone: Mesa, the CoreAnimation bridge, libsweet-fix, the audio plug-in, the Bluetooth library.
tools/Device-tree builder, boot packer, iOS root builder, firmware pullers, log and crash tools.
tools/root-files/One-boot lists that add, move or remove files on the iOS root.
.github/workflows/CI for the kernel and the programs, and an analysis job for iOS's libraries (nothing from Apple is stored).
NOTES.mdThe engineering log: every boot's result, the current state and the next steps.

FAQ

Can it run iOS 17, 18 or 26?

Not without a different approach. iOS 16 is the last release built for the iPhone X, the newest whose code runs on a processor without pointer authentication (ARMv8.3 PAC), and the Snapdragon 865 has none. Newer releases also draw only through Metal, while this port drives the GPU through Mesa's OpenGL ES.

Is Android gone?

Its userdata is replaced by the iOS root; the bootloader, recovery, modem and persist stay. Every iOS boot is a temporary fastboot boot.

Does Metal work?

No. There is no Metal device; libsweet-fix.dylib keeps the few programs that assume one (the screenshot markup) from crashing.

Is anything from Apple in the repository?

No. iOS, its firmware and its libraries are downloaded by you and never committed or uploaded by CI.
